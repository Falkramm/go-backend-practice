# GO-C09 · Простой rate limiter без накопления burst

Реализация прошла тесты и проверку `-race` 16 ноября 2026 года.

Ограничитель задаёт минимальный интервал между разрешениями и поддерживает конкурентных ожидающих.

## Контракт

```go
NewLimiter(interval time.Duration, c clock.Clock) (*Limiter, error)
(*Limiter).Wait(ctx context.Context) error
```

- Положительный interval создаёт ограничитель, нулевой и отрицательный дают nil и ошибку. Передавай инициализированный clock.Clock и ненулевой context.
- Первое разрешение выдаётся сразу. Между последующими выдачами проходит минимум interval по переданному clock.
- Длительный простой даёт одно немедленное разрешение. Следующее выдаётся спустя interval.
- Успех возвращает nil. Заранее отменённый context возвращает распознаваемую через errors.Is ошибку context перед выдачей разрешения.
- Отмена ожидающего возвращает ошибку context и сохраняет ближайшее разрешение для следующего вызывающего.
- Wait поддерживает одновременные вызовы. После завершения всех ожидающих активные таймеры освобождены.

## Работа с готовыми тестами

Реализация находится в `exercise.go`, проверки — в `exercise_test.go`.

Тесты используют internal/testclock, явную готовность хотя бы одного таймера и ручное продвижение времени. Порядок ожидания конкурентных клиентов выбирает реализация. Проверяется интервал между фактически выданными разрешениями. Дополнительный smoke-тест с clock.Real проверяет возврат DeadlineExceeded при ожидании с конечным context.

Команды выполняются из этой папки.

```sh
go test -timeout=30s -v .
go test -timeout=30s -race -count=1 .
```
