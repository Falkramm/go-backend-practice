# GO-C10 · Token bucket по ключам и время ожидания

Реализация прошла тесты и проверку `-race` 16 ноября 2026 года.

Token bucket проверяет доступ по строковому ключу и возвращает время до следующей попытки.

## Контракт

```go
NewBucket(capacity int, rate int, c clock.Clock) (*Bucket, error)
(*Bucket).Access(key string) (allowed bool, retryAfter time.Duration)
```

- `capacity` задаёт максимальный запас токенов для каждого ключа, `rate` — целое число токенов в секунду. Оба параметра имеют тип `int` и положительны. Нулевые и отрицательные значения дают `nil` и ошибку конструктора.
- Все ключи используют общие настройки и независимый запас токенов. При первом обращении ключ получает `capacity` токенов. Пустая строка — допустимый ключ.
- `Access` выполняет проверку сразу. При наличии целого токена атомарно расходует один и возвращает `true, 0`.
- При нехватке возвращает `false, retryAfter`, где задержка положительна. Отказ сохраняет накопленные токены. Повторные отказы в один момент времени дают одинаковую задержку.
- Баланс токенов целочисленный. За каждую полную прошедшую секунду прибавляется `rate` токенов, запас ограничен `capacity`.
- Секундные интервалы отсчитываются от создания записи ключа. После пополнения точка отсчёта сдвигается на число учтённых полных секунд. Например, обращение через полсекунды сохраняет ближайшее пополнение на границе первой секунды.
- Ожидание округляется вверх до целой секунды. При отказе `retryAfter` равен `time.Second`, поскольку за следующую секунду поступит как минимум один токен.
- `retryAfter` рассчитывается по текущему состоянию ключа. Другие успешные обращения к этому ключу могут изменить время доступности следующего токена.
- `Access` поддерживает одновременные обращения к одному и разным ключам. Проверка, пополнение и расход токена составляют одну атомарную операцию.
- Всё время берётся из переданного `clock.Clock`. Передавай инициализированные часы с неубывающим временем. Пополнение рассчитывается при обращении к ключу.

Например, при `capacity = 3` и `rate = 2` три обращения к `"alice"` в один момент успешны, четвёртое возвращает `false, time.Second`. Обращение к `"bob"` успешно сразу. Через полсекунды повторная проверка `"alice"` возвращает `false, time.Second`. На границе первой секунды для `"alice"` доступны два новых токена.

## Работа с готовыми тестами

Реализация находится в `exercise.go`, проверки — в `exercise_test.go`.

Тесты используют `internal/testclock` и ручное продвижение времени. Проверяются независимость ключей, начальный burst, пополнение по полным секундам, сохранение секундных интервалов, частые отказы, длительный простой и конкурентный доступ.

Команды выполняются из этой папки.

```sh
go test -timeout=30s -v .
go test -timeout=30s -race -count=1 .
```
