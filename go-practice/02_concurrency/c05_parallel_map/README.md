# GO-C05 · Параллельный map с сохранением порядка

Реализация прошла тесты и проверку `-race` 16 ноября 2026 года.

ParallelMap(ctx, items, concurrency, fn) обрабатывает входной список параллельно. Одновременно выполняется не больше concurrency вызовов, результаты возвращаются в порядке входных элементов. Первая ошибка прекращает запуск новой работы и отменяет оставшуюся через context. Перед возвратом дождаться запущенных обработчиков.

Проверить искусственно перемешанный порядок завершения, concurrency=1, пустой список, некорректный лимит, ошибку в середине и внешнюю отмену. Обработчик в проверках обязан реагировать на context.

## Контракт

```go
func ParallelMap(ctx context.Context, items []int, concurrency int, fn func(context.Context, int) (int, error)) ([]int, error)
```

`concurrency` положителен. Пустой ввод с корректными параметрами даёт пустой результат и `nil`. Успешный результат сохраняет порядок входа, включая повторяющиеся значения. При достаточном числе элементов функция допускает совместное выполнение `concurrency` обработчиков, удерживаемых тестовыми барьерами. Фактическое число активных вызовов ограничено этим лимитом.

При первой ошибке прекращается запуск новой работы, context обработчиков отменяется. Перед возвратом функция дожидается всех уже запущенных обработчиков. Результат ошибки — `nil` и ошибка, сохраняющая исходную причину для `errors.Is`. Внешняя отмена возвращает `nil` и ошибку, распознаваемую через `errors.Is(err, ctx.Err())`. Заранее отменённый context даёт такую ошибку и для пустого ввода.

Передавай ненулевой context и обработчик. Обработчики кооперативно реагируют на переданный context.

## Работа с готовыми тестами

Реализация находится в `exercise.go`, проверки — в `exercise_test.go`.

```sh
go test -timeout=30s -v .
go test -timeout=30s -race -count=1 .
```

Тесты управляют порядком завершения, моментом ошибки и возвратом отменённых обработчиков через барьеры. Таймаут в две секунды ограничивает ожидание. Максимум активных вызовов измеряется атомарным счётчиком.
