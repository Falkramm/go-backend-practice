# GO-C04 · Worker pool с ограниченной очередью

Реализация прошла тесты и проверку `-race` 16 ноября 2026 года.

В упражнении реализованы создание пула и отправка задания с context. Пул запускает `workers` работников и создаёт входную очередь ёмкости `queueSize`.

## API

```go
type Job struct { ID, Value int }
type Result struct { ID, Value int; Err error }
type Pool struct {
    Jobs chan<- Job
    Results <-chan Result
    Done <-chan struct{}
}

func NewPool(ctx context.Context, workers, queueSize int, fn func(context.Context, int) (int, error)) (*Pool, error)
func Submit(ctx context.Context, jobs chan<- Job, job Job) error
```

`NewPool` возвращает работающий пул сразу. Требуются `workers > 0`, `queueSize >= 0`, ненулевые `ctx` и `fn`. Нулевая очередь допустима. Ошибка параметров возвращает `nil, error`. При корректных параметрах заранее отменённый `ctx` даёт `nil` и ошибку, распознаваемую через `errors.Is(err, ctx.Err())`, до запуска работников.

## Обработка задания

- `fn` получает `Job.Value` и context пула.
- `Result.ID` сохраняет `Job.ID`, а `Result.Value` и `Result.Err` содержат оба результата вызова `fn`.
- Ошибка одного вызова попадает в его `Result.Err`; обработка остальных заданий продолжается.
- При штатном завершении на каждую принятую запись приходит ровно один результат. ID могут повторяться. Порядок результатов произвольный.
- Одновременно выполняется максимум `workers` вызовов `fn`. При достаточном количестве заданий все работники доступны для параллельной обработки. Пока все они заняты, очередь удерживает ещё `queueSize` заданий.

## Кто закрывает каналы

| Канал | Владелец закрытия | Момент |
| --- | --- | --- |
| `Jobs` | Код, подающий задания | После возврата всех своих вызовов `Submit` |
| `Results` | Пул | После завершения всех работников |
| `Done` | Пул | После закрытия `Results` |

`Done` — финальное уведомление о завершении пула.

## Штатный порядок работы

1. Создай пул и запусти чтение `Results` параллельно подаче заданий. Канал результатов может быть небуферизованным.
2. Отправляй задания через `Submit` или напрямую в `Jobs`.
3. После завершения всех отправок закрой `Jobs` со стороны отправителя.
4. Работники обрабатывают оставшуюся очередь и завершаются. Пул закрывает `Results`, затем `Done`.
5. Дочитай `Results` до закрытия и дождись `Done`.

Чтение результатов продолжается, пока работники публикуют их. Это позволяет завершить обработку и подачу при заполненных каналах.

## Отмена

Отмена `ctx` из `NewPool` останавливает весь пул, включая ожидание задания и отправку результата. Обработчики кооперативно реагируют на переданный context. После их возврата пул закрывает `Results` и `Done`, в том числе когда потребитель перестал читать результаты. При отмене часть принятых заданий и результатов может остаться необработанной.

`Jobs` остаётся под управлением отправителя. Он закрывает канал один раз после окончания всех своих отправок. Для `Submit` используй context пула или его дочерний context, чтобы отмена завершала и ожидание места в очереди.

## Submit

`Submit` передаёт одну запись в открытый `jobs`. Пока очередь заполнена, вызов ждёт свободного места или отмены своего context. Успешный возврат подтверждает приём в очередь; завершение обработки подтверждает `Result`.

Заранее отменённый context возвращает ошибку, распознаваемую через `errors.Is(err, ctx.Err())`, и сохраняет содержимое очереди. Отправитель завершает свои вызовы `Submit` до закрытия `Jobs`.

## Готовые тесты

Пул, вспомогательная отправка и их совместная работа проверяются отдельными группами.

```sh
go test -timeout=30s -v -run '^(TestPool|TestNewPool)' .
go test -timeout=30s -v -run '^TestSubmit' .
go test -timeout=30s -v -run '^TestIntegrationPoolAndSubmit$' .
go test -timeout=30s -race -count=1 .
```

Проверяются результаты и ошибки, повторяющиеся ID, пустой ввод, ёмкость очереди, максимум активных обработчиков, отмена и закрытие каналов. Барьеры управляют состоянием работников, таймаут в две секунды ограничивает ожидание.
